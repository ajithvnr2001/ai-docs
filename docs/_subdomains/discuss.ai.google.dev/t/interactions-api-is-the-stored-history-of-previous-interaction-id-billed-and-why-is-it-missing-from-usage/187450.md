Starting June 19, 2026, the Gemini API will stop accepting requests from unrestricted API keys to prevent unauthorized usage and billing risks.
If your Google Cloud project has the Gemini API enabled and contains unrestricted keys, please restrict them immediately.
###  [](https://discuss.ai.google.dev/t/interactions-api-is-the-stored-history-of-previous-interaction-id-billed-and-why-is-it-missing-from-usage/187450#p-311902-what-to-do-1)What to do:
  * Option 1 (Restrict existing keys): Go to [Google Cloud Credentials](https://console.cloud.google.com/apis/credentials), select your key, and under API restrictions, restrict it to Gemini API ([generativelanguage.googleapis.com](http://generativelanguage.googleapis.com)).
  * Option 2 (New keys): Generate new restricted keys in [Google AI Studio](https://aistudio.google.com/app/apikey) and update your code.


Note: Keys generated directly in AI Studio are restricted to the Gemini API by default.

With store=true and previous_interaction_id on gemini-3.1-pro-preview, a follow-up turn after a 24.7k-token turn reports usage.total_input_tokens = 11, while an undocumented field raw_prompt_token shows 24,750, and the model clearly reads the earlier content. The Interactions docs say usage includes the conversation history.
Questions:
  1. Is the stored history billed as input on each follow-up turn, and at which rate (standard, cached, or not at all)?
  2. Which usage field reflects the billed input tokens?
  3. Does implicit caching apply to the stored history, and is it reported in cached_tokens?


Context: a multi-turn agent with Google Search, URL context and function calling, about 30 follow-up turns per task. We’re deciding whether to move from generateContent to Interactions and need the billing to be predictable.

Hello [@Marius3](https://discuss.ai.google.dev/u/marius3) ,
Thank you for flagging this. Stored conversation history passed via `previous_interaction_id` is processed as input context (and is eligible for implicit caching), so it should be reflected in `usage.total_input_tokens` and `usage.total_cached_tokens`.
We are looking into the issue where `usage.total_input_tokens` only displays the new turn’s tokens on follow-up turns and will share an update here once resolved.
