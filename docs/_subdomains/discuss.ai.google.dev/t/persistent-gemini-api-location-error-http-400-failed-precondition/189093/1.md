Hi Everyone,
Starting June 19, 2026, the Gemini API will stop accepting requests from unrestricted API keys to prevent unauthorized usage and billing risks.
If your Google Cloud project has the Gemini API enabled and contains unrestricted keys, please restrict them immediately.
###  [](https://discuss.ai.google.dev/t/persistent-gemini-api-location-error-http-400-failed-precondition/189093#p-311902-what-to-do-1)What to do:
  * Option 1 (Restrict existing keys): Go to [Google Cloud Credentials](https://console.cloud.google.com/apis/credentials), select your key, and under API restrictions, restrict it to Gemini API ([generativelanguage.googleapis.com](http://generativelanguage.googleapis.com)).
  * Option 2 (New keys): Generate new restricted keys in [Google AI Studio](https://aistudio.google.com/app/apikey) and update your code.


Note: Keys generated directly in AI Studio are restricted to the Gemini API by default.

**Subject: Persistent Gemini API regional access error despite successful connectivity and supported-region IP**
Hello Google AI Support Team,
Thank you for your response.
I have performed additional diagnostic tests, but the issue remains unresolved.
I am developing an AI-powered legal assistant using the Gemini API, Python, and Supabase. I use the gemini-embedding-2 model to generate embeddings for a legal document search system.
The API consistently returns the following error:
HTTP 400 — FAILED_PRECONDITION
User location is not supported for the API use.
I have now confirmed the following:
  1. My Python script can successfully connect to Google’s API endpoint.
  2. My external IPv4 address is geolocated to Ashburn, Virginia, United States, through the FDCserversnet network.
  3. The same error occurs when I query the general Gemini API model list endpoint (/v1beta/models), without requesting embeddings.
  4. The error persists when calling the API using gemini-embedding-2:embedContent.
  5. I previously tested VPN endpoints in Finland and the United States, but the error remained unchanged.
  6. The API key is successfully read from my local environment file. I have not included the key in this report.


Since the error occurs both when listing models and when generating embeddings, it does not appear to be limited to the embedding model itself.
Could you please investigate whether this error may be caused by an account-level or Google Cloud project restriction, an incorrect regional eligibility determination, or another server-side access control?
If possible, please clarify which eligibility check is failing and what specific action is required to restore API access.
I would appreciate a technical investigation rather than further general recommendations to change VPN servers, as I have already tested multiple locations.
Thank you for your assistance.
Best regards
