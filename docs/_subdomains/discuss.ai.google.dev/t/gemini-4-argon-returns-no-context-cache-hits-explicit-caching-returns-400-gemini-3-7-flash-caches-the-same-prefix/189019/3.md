Title: gemini-4-argon returns no context cache hits; explicit caching returns 400 (gemini-3.7-flash caches the same prefix)
Hi, I’m seeing no context cache hits on gemini-4-argon, while gemini-3.7-flash caches the same prefix in the same session.
Setup
- Date: 2026-10-13
- Prefix: systemInstruction of ~36k tokens (1500 numbered lines), identical across calls
- Only the final user question changes between calls
- 15 s between calls, no tools, maxOutputTokens 30
Results (cachedContentTokenCount from usageMetadata)
- gemini-4-argon, AI Studio, 3 calls: 0, 0, 0 (promptTokenCount ~36,172-36,176)
- gemini-4-argon, Vertex AI global, 3 calls: 0, 0, 0
- gemini-3.7-flash, AI Studio, 3 calls: 0, 0, 34,093 (hit only on the 3rd call)
- gemini-3.7-flash, explicit cache (cachedContents, ttl 600s), 2 calls: 36,125 and 36,125 read
Explicit cache on Argon
- POST /v1beta/cachedContents with model models/gemini-4-argon
- Returns 400: “Explicit caching is not supported for models/gemini-4-argon”
Question
The model page says explicit caching is not supported, and the implicit caching table lists Gemini 4 Argon with a 4,096-token minimum. Is implicit caching expected to work on gemini-4-argon? If yes, what conditions are needed beyond the minimum? If no, can the table be updated?
Impact: agent sessions with a large stable prefix pay the full input price on every turn.

Hello [@iseixas](https://discuss.ai.google.dev/u/iseixas) ,
Thank you for the detailed reproduction script. Explicit caching (`cachedContents`) is not supported for `gemini-4-argon` by design, as Gemini 4 models rely on implicit caching (see the [Context caching documentation](https://ai.google.dev/gemini-api/docs/caching)).  
We are looking into the implicit caching behavior you reported.
