Hi Everyone,
Starting June 19, 2026, the Gemini API will stop accepting requests from unrestricted API keys to prevent unauthorized usage and billing risks.
If your Google Cloud project has the Gemini API enabled and contains unrestricted keys, please restrict them immediately.
###  [](https://discuss.ai.google.dev/t/handling-429-503-errors-from-the-gemini-api/124640#p-311902-what-to-do-1)What to do:
  * Option 1 (Restrict existing keys): Go to [Google Cloud Credentials](https://console.cloud.google.com/apis/credentials), select your key, and under API restrictions, restrict it to Gemini API ([generativelanguage.googleapis.com](http://generativelanguage.googleapis.com)).
  * Option 2 (New keys): Generate new restricted keys in [Google AI Studio](https://aistudio.google.com/app/apikey) and update your code.


Note: Keys generated directly in AI Studio are restricted to the Gemini API by default.

If you’re experiencing 429 or 503 errors when accessing the Gemini API, please read on.
#  [](https://discuss.ai.google.dev/t/handling-429-503-errors-from-the-gemini-api/124640#p-234342-h-503-errors-1)503 errors
503 errors are unrelated to your quota and indicate our services are temporarily overloaded and can’t service your request. These errors are more common during certain times of the day. We apologise for the impact of these errors & are working hard to provision more resources and reduce their occurrence.
To handle these errors, we strongly recommend implementing backoff and retry (our SDKs support this through _retry config_). Although your requirements will vary based on your desired user experience, you can try setting a low number of retries with a short timeout at first, and increase these if the issue isn’t resolved.
If applicable, you could also consider moving non-realtime jobs to our[ Batch API](https://ai.google.dev/gemini-api/docs/batch-api?batch=file).
#  [](https://discuss.ai.google.dev/t/handling-429-503-errors-from-the-gemini-api/124640#p-234342-h-429-errors-2)429 errors
We recently made some backend updates to ensure that _all_ 429 errors come with a description field which properly explains the cause. We recommend scanning your logs for these. While a lot of pertinent information is currently available in the AI Studio [Usage](https://aistudio.google.com/usage), [Rate Limit](https://aistudio.google.com/rate-limit) & [Billing](https://aistudio.google.com/billing) pages, we’re working to make the cause of 429 errors easier to find in AI Studio. Please see below for advice on specific categories of 429 errors.
##  [](https://discuss.ai.google.dev/t/handling-429-503-errors-from-the-gemini-api/124640#p-234342-tier-drop-3)**Tier drop**
If your account has recently experienced a tier drop (e.g. tier 3→2 or 2→1). This is very likely the root cause of the 429’s as lower tiers come with lower rate limits & spend caps.
This happens if an automated flag is applied to your account. Unfortunately our support team can’t check or remove these flags. Please check for banners / error callouts in the AI Studio [Projects page](https://aistudio.google.com/projects) & the [Billing page](https://aistudio.google.com/billing). You should also check whether you’ve received an email from us with an appeal link.
##  [](https://discuss.ai.google.dev/t/handling-429-503-errors-from-the-gemini-api/124640#p-234342-prepay-funds-depleted-4)**Prepay funds depleted**
If your prepay balance is depleted, we’re unable to serve responses. Generally this can be fixed by [buying credits](https://ai.google.dev/gemini-api/docs/billing#buy-credits). Note that GCP Free Trial credits can’t be used to pay for Gemini API usage ([details](https://ai.google.dev/gemini-api/docs/billing#free-trial-through-ais)).
##  [](https://discuss.ai.google.dev/t/handling-429-503-errors-from-the-gemini-api/124640#p-234342-spend-cap-exceeded-5)**Spend cap exceeded**
We return 429 errors if a spend cap is exceeded.
  * Please see [Billing account tier spend caps](https://ai.google.dev/gemini-api/docs/billing#tier-spend-caps) for more information.
  * You should also check whether you set a [Project spend cap](https://ai.google.dev/gemini-api/docs/billing#spend-caps).


##  [](https://discuss.ai.google.dev/t/handling-429-503-errors-from-the-gemini-api/124640#p-234342-rate-limits-6)**Rate limits**
Multiple different types of rate limits can result in 429 errors. You should check the AI Studio [Rate Limits](https://aistudio.google.com/rate-limit) page to see details of these. Notes:
  * Be sure to select the applicable project & time range.
  * Take special care to check the Search grounding & Map grounding limits further down the page
  * If you’re running into limitations from RPM or TPM limits, consider implementing backoff and retry with a long maximum delay (our SDKs support this through _retry config_).
