Hi Everyone,
Starting June 19, 2026, the Gemini API will stop accepting requests from unrestricted API keys to prevent unauthorized usage and billing risks.
If your Google Cloud project has the Gemini API enabled and contains unrestricted keys, please restrict them immediately.
###  [](https://discuss.ai.google.dev/t/gemini-3-8-tts-voice-consistency-issue/186103/17#p-311902-what-to-do-1)What to do:
  * Option 1 (Restrict existing keys): Go to [Google Cloud Credentials](https://console.cloud.google.com/apis/credentials), select your key, and under API restrictions, restrict it to Gemini API ([generativelanguage.googleapis.com](http://generativelanguage.googleapis.com)).
  * Option 2 (New keys): Generate new restricted keys in [Google AI Studio](https://aistudio.google.com/app/apikey) and update your code.


Note: Keys generated directly in AI Studio are restricted to the Gemini API by default.

I’m experiencing severe voice drift and voice inconsistency with Gemini 3.8 TTS, even when using Google’s official preset voices.
Even when I use **the exact same preset voice, identical API parameters, and the exact same text** , repeated generations can produce completely different-sounding voices. The inconsistency is unpredictable and extremely frustrating.
The problem becomes even worse with long-form text. Voice drift happens frequently during a single generation, making it nearly impossible to maintain a consistent voice throughout a long narration. **Sometimes, a female voice suddenly turns into a male voice in the middle of the audio!**
What’s particularly frustrating is that Gemini 3.8 TTS is actually excellent in terms of naturalness, audio quality, and pricing. It has enormous potential. However, **this bizarre and severe voice consistency issue makes it practically unusable for real-world production.**
Please prioritize fixing this bug as soon as possible!
Frankly, I find it hard to believe that proper quality testing was conducted before this model was released. This is such a fundamental and easily noticeable problem that I’m genuinely shocked it wasn’t caught during internal testing.
**How could such an obvious and critical issue make it into a public release?**
I really hope the engineering team takes this seriously and provides a fix soon. Voice consistency is not an optional feature for a TTS model — it is one of the most basic requirements.
