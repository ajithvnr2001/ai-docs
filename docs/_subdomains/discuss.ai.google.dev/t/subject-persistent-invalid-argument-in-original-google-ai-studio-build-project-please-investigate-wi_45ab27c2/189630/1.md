Hi Everyone,
Starting June 19, 2026, the Gemini API will stop accepting requests from unrestricted API keys to prevent unauthorized usage and billing risks.
If your Google Cloud project has the Gemini API enabled and contains unrestricted keys, please restrict them immediately.
###  [](https://discuss.ai.google.dev/t/subject-persistent-invalid-argument-in-original-google-ai-studio-build-project-please-investigate-without-destructive-recovery/189630#p-311902-what-to-do-1)What to do:
  * Option 1 (Restrict existing keys): Go to [Google Cloud Credentials](https://console.cloud.google.com/apis/credentials), select your key, and under API restrictions, restrict it to Gemini API ([generativelanguage.googleapis.com](http://generativelanguage.googleapis.com)).
  * Option 2 (New keys): Generate new restricted keys in [Google AI Studio](https://aistudio.google.com/app/apikey) and update your code.


Note: Keys generated directly in AI Studio are restricted to the Gemini API by default.

I need assistance recovering my existing project:
  * Project: THƯ VIỆN QR THCS — Trường TH&THCS Nguyễn Khoa Đăng
  * Original project: <https://th-vi-n-qr-thcs.ai.studio/>
  * GitHub repository: <https://github.com/hopphan-eng/thuvienthcs>
  * Production deployment: thuvienqr.vercel.app
  * Firebase project: thuvienthcs
  * Original applet ID recorded during prior diagnostics: e580688e-7e04-48cd-bb5e-400df852ca55


**Problem**
Google AI Studio Build returns `Invalid argument` for prompts, including simple diagnostic prompts. The original project preview and source code have remained visible, but the Build assistant cannot reliably process requests.
Previous diagnostics also showed failed uploads returning HTTP 404 and WebSocket connection failures to the AI Studio development environment.
A separate blank AI Studio project has worked normally, while the original project has continued to experience the problem.
**Requested investigation**
  1. Check the original applet’s Build session, project state, request payload validation and backend logs.
  2. Determine whether the issue is caused by corrupted conversation context, an invalid project snapshot, or a Build service problem.
  3. Provide a supported recovery procedure that preserves the existing source code and project identity.
  4. Confirm whether recovery is possible without recreating the Firebase project or modifying application data.


**Critical preservation requirements**
Please do not recommend destructive recovery without a verified backup. The application uses Firebase Authentication, Firestore, role-based access control and existing library transaction data. These must remain intact.
I would appreciate a diagnosis of the existing project rather than instructions to rebuild the application from scratch.
Thank you.
